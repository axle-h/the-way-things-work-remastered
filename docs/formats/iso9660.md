# Disc image (ISO 9660)

The disc is a plain ISO 9660 volume, the public standard ECMA-119. The desktop app reads the user's image directly, and `pnpm data` uses the same reader to extract it to `vendor/cd`. The reader is `packages/formats/src/iso9660/`. This page lists what the reader relies on and what this disc actually uses.

All facts marked [V] were checked over the whole image: the corpus test (`tools/data/src/iso.corpus.test.ts`) walks every directory and compares every file byte for byte with an independent `7z` extraction. The extraction by `pnpm data` was also compared with that `7z` extraction using `diff -r`, including modification times, and they matched.

## What this disc uses [V]

| Property | Value |
|---|---|
| Volume descriptors | Primary (sector 16), then the terminator (sector 17). No boot record, no supplementary descriptor, so **no Joliet** |
| Rock Ridge / SUSP | **None**: the root's `.` record has no system use area |
| Volume label | `DKMMTWTW` |
| Logical block size | 2,048 bytes |
| Volume space | 139,720 blocks. The image file has 300 more sectors, all zero, after the volume (a ripping artefact) |
| Interchange level | Level 1 in practice: upper-case 8.3 names (at most 12 characters with the dot), at most 3 levels deep |
| Contents | 2,337 files in 211 directories (plus the root) |
| File identifiers | Every file has the `;1` version suffix and an extension. Directories have no suffix |
| File records | One extent per file. No multi-extent files, no interleaving, no extended attribute records, no hidden or associated files |
| Directories | 1 to 3 blocks each; seven span more than one block |
| Recording dates | Every directory record has UTC offset 0. Dates are read as UTC, which is also what `7z` does |
| Volume dates | Created, modified and effective are `1994080916175700`. Expiry is unset. Their offset byte is `0x30` (ASCII `0`), which under ECMA-119 means UTC+12:00. The mastering tool probably meant offset 0. The reader follows the standard; nothing uses these dates |
| Both-endian fields | The little-endian and big-endian halves agree everywhere the reader checks |

## Structures the reader uses

These come from ECMA-119. Offsets are in bytes.

**Volume descriptors** start at byte 32,768 (sector 16), one per 2,048-byte sector, whatever the logical block size is. Each begins with a type byte, then `CD001`, then a version byte. The types are 0 boot record, 1 primary, 2 supplementary, 3 partition and 255 terminator. The reader stops at the terminator. It fails if there is no terminator within 64 descriptors or before the image ends, if any identifier is not `CD001`, or if there is no primary descriptor. A supplementary descriptor whose escape sequences (offset 88) start with `%/@`, `%/C` or `%/E` is Joliet. Its presence is reported but its tree is not read.

**Primary volume descriptor** fields the reader reads:

| Offset | Size | Field |
|---|---|---|
| 8 | 32 | System identifier (a-characters, space-padded) |
| 40 | 32 | Volume identifier (the label) |
| 80 | 4+4 | Volume space size in blocks (LE then BE) |
| 120 | 2+2 | Volume set size |
| 124 | 2+2 | Volume sequence number |
| 128 | 2+2 | Logical block size (the reader accepts 512, 1,024 or 2,048) |
| 132 | 4+4 | Path table size (the path tables themselves are not used) |
| 156 | 34 | Directory record of the root directory |
| 190 | 128 × 4 | Volume set, publisher, data preparer and application identifiers |
| 702 | 37 × 3 | Copyright, abstract and bibliographic file identifiers |
| 813 | 17 × 4 | Creation, modification, expiration and effective dates: `YYYYMMDDHHMMSScc` as digits, then a signed offset from UTC in 15-minute units. All zeros means not set |
| 881 | 1 | File structure version (1) |

**Both-endian numbers** store the value twice, little-endian first. The reader uses the little-endian half. By default it fails if the two halves differ; the `checkBothEndian: false` option turns that check off.

**Directory records** (a directory's extent is a sequence of them):

| Offset | Size | Field |
|---|---|---|
| 0 | 1 | Record length |
| 1 | 1 | Extended attribute record length, in blocks. The file data starts that many blocks after the extent location |
| 2 | 4+4 | Extent location (block) |
| 10 | 4+4 | Data length in bytes |
| 18 | 7 | Recording date: years since 1900, month, day, hour, minute, second, and a signed UTC offset in 15-minute units. All zeros means not set |
| 25 | 1 | Flags: `0x01` hidden ("existence"), `0x02` directory, `0x04` associated file, `0x08` record format, `0x10` protection, `0x80` multi-extent (not the final record of the file) |
| 26 | 1 | File unit size (interleaving) |
| 27 | 1 | Interleave gap size |
| 28 | 2+2 | Volume sequence number |
| 32 | 1 | Identifier length *n* |
| 33 | *n* | Identifier. `0x00` is the directory itself (`.`), `0x01` its parent (`..`) |
| 33 + *n* | 0 or 1 | A padding byte when *n* is even |
| … | rest | System use area (SUSP and Rock Ridge live here) |

A record never crosses a block boundary. A zero length byte means the rest of the block is padding, and the next record starts in the next block. Within a directory, the reader:

- skips `.` and `..`;
- skips associated files, such as Macintosh resource forks;
- joins a run of records with the same identifier into one multi-extent file, where every record but the last has flag `0x80`;
- strips the `;n` version and a trailing `.` from the name. If several versions of a name exist, it keeps the first one, which is the highest version because records are sorted that way;
- rejects identifiers that would be unsafe as path components (`/`, `\`, NUL, `.` or `..`).

It reports interleaved files (file unit size or gap not zero) and refuses to read them. Rock Ridge is reported when the root's `.` record starts its system use area with the SUSP `SP` entry (`SP`, length 7, version 1, `BE EF`) and also holds an `RR`, `PX`, `NM` or `ER` entry.

## Paths

Paths use `/` and are relative to the root. Leading, doubled and `.` segments are ignored. Lookup ignores case: names are compared in upper case, the case the disc uses. Paths reported by the reader keep the disc's own case, e.g. `DKCODE/TWTW.PNG`. `7z` and our extraction produce the same names: upper case, without `;1`.
